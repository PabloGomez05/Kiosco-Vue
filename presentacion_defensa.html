Presentación del proyecto

¿Qué desarrollamos?

Una SPA de gestión de stock con las cuatro operaciones CRUD

Objetivo del proyecto Construimos un sistema visualmente atractivo y moderno para administrar el inventario de un kiosco. Permite crear, leer, actualizar y eliminar productos. Para concentrarnos en la arquitectura Vue, los datos viven en memoria: al recargar la página vuelven a su estado inicial, dándonos total control sobre el flujo de datos.
➕

Create

Añadir nuevos productos (nombre, categoría, precio, stock).

📋

Read

Mostrar la lista de productos y filtrar por nombre en tiempo real.

✏️

Update

Editar la información (como el precio o stock) de un producto existente.

🗑️

Delete

Eliminar un producto del inventario con su respectiva confirmación.

🧩 Piezas de nuestra Arquitectura

  • App.vue — El componente raíz, dueño absoluto del estado global (lista de productos).
  • ProductoForm.vue — Formulario reutilizable que sirve tanto para añadir como para editar.
  • ProductoLista.vue — La tabla visual, con lógica condicional para alertas de bajo stock.
Puesta en marcha

Preparación del entorno y creación del proyecto

Node.js + Vite: Velocidad y eficiencia de desarrollo

1️⃣ Dependencias Core

Utilizamos Node.js como motor principal, y nos decantamos por Vite en lugar del Vue CLI clásico debido a su arranque instantáneo y HMR ultrarrápido, ideal para componentes SFC.

2️⃣ Instanciación

El proyecto se generó limpio y sin dependencias pesadas como Router o Vuex/Pinia, ya que centralizamos el estado localmente.

Construyendo Componentes

ProductoLista.vue — tabla visual y reactiva

props para recibir datos, emit para reaccionar

Rol del componente: "Componente Tonto (Dumb Component)" ProductoLista no guarda estado, ni procesa borrados internamente. Su único trabajo es renderizar el array de productos que App.vue le manda vía props, e incorporar reglas visuales (ej. insignias de stock bajo). Si el usuario clickea un botón, este componente se limita a emitir un evento.
ProductoLista.vue (fragmento)vue
<template>
  <tr v-for="producto in productos" :key="producto.id">
    <td>{{ producto.nombre }}</td>
    <td>
      <span v-if="producto.stock < 5">⚠️</span> 
      {{ producto.stock }} uds.
    </td>
    <td>
      <button @click="emit('editar', producto.id)">✏️</button>
      <button @click="emit('eliminar', producto.id)">🗑️</button>
    </td>
  </tr>
</template>

<script setup>
defineProps({ productos: { type: Array, required: true } })

const emit = defineEmits(['editar', 'eliminar'])
</script>
Construyendo Componentes

ProductoForm.vue — creación y edición unificada

v-model.number y watch para transiciones fluidas

Doble propósito En vez de tener dos formularios (uno para crear, otro para editar), hacemos uno inteligente. Mediante un watch monitoreamos si App.vue nos inyecta un producto. Si ocurre, los `ref()` se rellenan automáticamente; si no, el formulario se limpia y queda listo para añadir algo nuevo.
ProductoForm.vue (fragmento)vue
<script setup>
import { ref, watch } from 'vue'

const props = defineProps({ producto: { type: Object, default: null } })
const emit = defineEmits(['guardar', 'cancelar'])

const nombre = ref('')
const precio = ref(null)
const stock = ref(null)

watch(() => props.producto, (nuevoProducto) => {
  if (nuevoProducto) {
    nombre.value = nuevoProducto.nombre
    precio.value = nuevoProducto.precio
    stock.value = nuevoProducto.stock
  } else {
    limpiarFormulario()
  }
}, { immediate: true })

function guardar() {
  emit('guardar', { nombre: nombre.value, precio: precio.value, stock: stock.value })
}
</script>
Arquitectura y Patrones

El Patrón "Props abajo, eventos arriba"

El flujo de información en Vue.js

App.vue (estado maestro: productos)
props (:productos)
↓
↑
emit (guardar/editar/eliminar)
ProductoLista.vue
ProductoForm.vue
¿Por qué este patrón? Si ProductoLista modificara el array de inventario por sí solo, el flujo se volvería impredecible. Emitiendo eventos garantizamos que existe un único punto de verdad (Single Source of Truth) en App.vue. Esto previene bugs difíciles de rastrear cuando las aplicaciones escalan.

App.vue — el cerebro del kiosco

Implementación de los Computed Properties y el Mutador Global

App.vue — <script setup>vue
import { ref, computed } from 'vue'

let siguienteId = 6
const productos = ref([
  { id: 1, nombre: 'Coca-Cola 500ml', categoria: 'Bebidas', precio: 1500, stock: 24 }
])
const productoEditando = ref(null)
const busqueda = ref('')

const productosFiltrados = computed(() => {
  const termino = busqueda.value.toLowerCase()
  return productos.value.filter(p => p.nombre.toLowerCase().includes(termino))
})

function guardarProducto(datosProducto) {
  if (productoEditando.value) {
    const indice = productos.value.findIndex(p => p.id === productoEditando.value.id)
    if (indice !== -1) productos.value[indice] = { ...datosProducto, id: productoEditando.value.id }
    productoEditando.value = null
  } else {
    productos.value.push({ ...datosProducto, id: siguienteId++ })
  }
}

function eliminarProducto(id) {
  productos.value = productos.value.filter(p => p.id !== id)
}
