Sistema de Gestión e Inventario para Kiosco

Punto de Venta (POS) reactivo en Vue.js 3 conectado a una API REST con JWT/RBAC y persistencia transaccional ACID en MySQL 8.0 (3FN)

Vue 3 + Composition API Vite Node.js API REST JWT + RBAC (403) MySQL 8.0 InnoDB (10 Tablas 3FN) OpenAPI 3.0.3
Alumno: Pablo Hernán Gómez  |  Docente: Prof. José Olivera
Alcance y Priorización

Alcance del MVP y Priorización MoSCoW

Foco en el núcleo transaccional de mostrador, control de inventario y seguridad por roles

Objetivo del Sistema Brindar un Punto de Venta (POS) ágil y confiable que garantice consistencia contable y de inventario en tiempo real: cada cobro valida stock bajo bloqueo transaccional, soporta pagos únicos o mixtos, audita movimientos y concilia el arqueo diario de caja.
🟢

Must Have (Núcleo MVP)

Login JWT + RBAC (403), Catálogo y Stock, Venta Transaccional ACID (Pago único/mixto), Cierre de Caja Diario.

🟡

Should Have

Historial auditable de precios (historial_precios), bitácora de stock y filtros por stock crítico.

🔵

Could Have

Reportes estadísticos por rango de fechas y exportación CSV de arqueos.

⚪

Won't Have (Fuera)

Facturación electrónica AFIP/ARCA, múltiples sucursales y app móvil nativa.

⚡ Flujos Principales del Punto de Venta

1
Venta con Descuento Atómico de Stock: Selección en catálogo, pago único o mixto (Efectivo + Transferencia) y actualización reactiva de inventario y bitácora.
2
Seguridad por Rol en Servidor (RBAC): Validación mediante middleware JWT; bloqueo con HTTP 403 Forbidden ante operaciones administrativas desde un perfil vendedor.
3
Control de Concurrencia en Stock Límite: Serialización de ventas simultáneas mediante bloqueo de filas para impedir valores de stock negativos.
4
Arqueo y Cierre de Caja Diario: Conciliación automática entre el efectivo esperado por ventas y el efectivo físico contado al cierre del turno.

¿Qué es Vue.js y cómo funciona en el proyecto?

Reactividad con ref() y computed() + Patrón "Props abajo, Eventos arriba"

Arquitectura Reactiva del Frontend Vue.js es un framework progresivo de JavaScript para construir interfaces de usuario basadas en componentes reutilizables y un sistema de reactividad automática. Cuando el estado en JavaScript cambia (por ejemplo, se descuenta el stock tras una venta o se suma un producto al carrito), Vue detecta el cambio y actualiza únicamente los nodos necesarios del HTML sin recargar el navegador.

async function procesarVenta(pagos) {
  // Generamos una clave única de idempotencia para evitar cobros duplicados por doble clic
  const idempotencyKey = `venta-pos-${Date.now()}-${Math.random().toString(36).slice(2, 7)}`

  const { status, data } = await llamarApi('/api/ventas', {
    method: 'POST',
    headers: { 'Idempotency-Key': idempotencyKey },

      items: itemsCarrito.value.map(i => ({ producto_id: i.producto_id, cantidad: i.cantidad })),
      pagos // Array de pagos: soporta pago único o pago mixto (1:N)

  })
  if (status === 201) {
    itemsCarrito.value = [] // Vacía el carrito reactivamente
    await cargarDatosOperativos() // Refresca stock, ventas y bitácora de movimientos
  }
}

Eliminamos metodo_pago de ventas. Ahora un ticket puede pagarse con múltiples medios (ej. Efectivo + Transferencia) sin redundancia.

📈

Separa el precio actual en productos de la evolución histórica de costos y precios de venta con fechas de vigencia.

📦

movimientos_stock

Bitácora inmutable que audita cada entrada, salida por venta o ajuste con stock_anterior y stock_resultante.

🧮

cierres_caja

Concilia al final del turno el efectivo esperado contra el efectivo físico contado en el cajón.

Persistencia Relacional

DDL Ejecutable en MySQL 8.0 (database/schema.sql)

DECIMAL(12,2), restricciones CHECK, ON DELETE RESTRICT, índices y utf8mb4

Decisión técnica en el DDL¿Cómo se implementó?¿Por qué es fundamental?
Montos exactosDECIMAL(12,2) en precios, subtotales, pagos y arqueos.Evita errores de redondeo de punto flotante binario (FLOAT/DOUBLE) en centavos.
Stock y cantidades válidasCHECK (stock_actual >= 0) y CHECK (cantidad > 0).El motor MySQL 8.0 rechaza cualquier intento de dejar inventario negativo.
Integridad referencialON DELETE RESTRICT ON UPDATE CASCADE en todas las FKs.Impide borrar físicamente productos o usuarios que ya tienen ventas históricas (se usa baja lógica activo = 0).
Columnas calculadasGENERATED ALWAYS AS (ROUND(cantidad * precio_unitario, 2)) STORED.El subtotal del renglón lo calcula el motor de base de datos, evitando inconsistencias.
Índices explícitosINDEX en todas las claves foráneas y campos fecha_hora.Acelera los JOIN y los arqueos de caja por rango de fecha sin hacer Full Table Scans.
database/schema.sql (Extracto MySQL 8.0 InnoDB)sql
CREATE TABLE productos (
    id                 INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    codigo_barras      VARCHAR(30)  NOT NULL,
    nombre             VARCHAR(120) NOT NULL,
    categoria_id       INT UNSIGNED NOT NULL,
    precio_costo       DECIMAL(12, 2) NOT NULL,
    precio_venta       DECIMAL(12, 2) NOT NULL,
    stock_actual       INT NOT NULL DEFAULT 0,
    activo             TINYINT(1) NOT NULL DEFAULT 1,
    CONSTRAINT fk_productos_categoria FOREIGN KEY (categoria_id)
        REFERENCES categorias (id) ON DELETE RESTRICT ON UPDATE CASCADE,
    CONSTRAINT chk_productos_precios CHECK (precio_costo >= 0 AND precio_venta >= precio_costo),
    CONSTRAINT chk_productos_stock   CHECK (stock_actual >= 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
Integridad Operativa (ACID)

Cómo conectamos la BD y blindamos la Venta Transaccional

Pool mysql2/promise + Bloqueo Pesimista SELECT ... FOR UPDATE + Rollback Automático

Doble capa de persistencia en server/services/ • ventaMysqlService.js: Conecta a MySQL 8.0 mediante un pool de conexiones (mysql2/promise) usando consultas parametrizadas con ? (previniendo SQL Injection) y transacciones reales.
• kioscoEngine.js: Motor transaccional en memoria con cola de bloqueo exclusivo (Mutex) y Rollback por snapshot que replica las 10 tablas para que la demo en vivo (npm run dev / npm run test:hito) funcione en cualquier PC sin configuración previa.
server/services/ventaMysqlService.js — Transacción ACID con Bloqueo de Filasjavascript
const conn = await pool.getConnection();
try {
  await conn.beginTransaction(); // 1. Inicia la transacción atómica

  // 2. Bloqueo pesimista (FOR UPDATE) ordenando IDs para prevenir Deadlocks
  for (const item of itemsOrdenados) {
    const [rows] = await conn.execute(
      'SELECT id, nombre, precio_venta, stock_actual FROM productos WHERE id = ? FOR UPDATE',
      [item.producto_id]
    );
    if (rows[0].stock_actual < item.cantidad) {
      throw new Error('STOCK_INSUFICIENTE'); // Dispara el catch -> ROLLBACK total
    }
  }
  // 3. Inserta cabecera (ventas), renglones (detalle_ventas), pagos (pagos_venta),
  //    descuenta stock (UPDATE productos) y graba auditoría (movimientos_stock)
  await conn.commit(); // 4. Confirma todos los cambios juntos
} catch (err) {
  await conn.rollback(); // Si falla cualquier paso, no se descuenta ni un solo producto
  throw err;
} finally {
  conn.release();
}
¿Qué pasa cuando 2 cajas intentan vender al mismo tiempo el último Alfajor (stock = 1)? La Transacción A ejecuta SELECT ... FOR UPDATE y bloquea la fila del producto. La Transacción B queda esperando en cola hasta que A hace COMMIT dejando el stock en 0. Recién ahí B lee el stock actualizado (0 < 1), ejecuta ROLLBACK y recibe HTTP 409 STOCK_INSUFICIENTE.

server/middlewares/auth.js — Verificación de Rol en Servidorjavascript
export function autorizarRol(...rolesPermitidos) {
  return (req, res, next) => {
    if (! rolesPermitidos.includes(req.user.rol)) {
      return enviarError(res, 403, 'ACCESO_DENEGADO',
        `Acceso denegado: el rol '${req.user.rol}' no tiene permisos para ${req.method} ${req.originalUrl}.`
      );
    }
    return next();
  };
}
